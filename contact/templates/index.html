03 / about

How I work

Small, reviewable changes. Clear data models. Tests where they earn their keep.

I start with the domain: what the entities are, how they relate, and what invariants must never break. Once the model is right, the interface tends to fall out of it.

From there I ship in thin vertical slices so there is always something running. I like the unglamorous parts too — migrations, background jobs, error budgets, and the logs you only read at 2am.
